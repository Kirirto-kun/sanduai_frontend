# SanduAI — Psycho Training & Creative Seminar Pro

Дата: 26 октября 2026. Статус: реализация и итоговая живая проверка завершены, стенд запущен локально. Production deployment не выполнялся.

## Требования и границы

Источник — полный бриф заказчика «SANDUAI — PSYCHO TRAINING & CREATIVE SEMINAR PRO» (18 разделов). Это отдельный конструктор профессиональных образовательных мероприятий, а не замена праздничных сценариев или существующих мастер-классов.

- 6 типов: психологический тренинг, креативный семинар, мастерская, тимбилдинг, стратегическая сессия, ученический тренинг.
- 8 режимов: идеи (5–7), полный сценарий I–XII, мастер-класс, игры (5–10), раздаточные материалы, план презентации, полный пакет, экспресс (5–15 минут).
- Казахский язык результата по умолчанию; русский и остальные языки платформы по выбору.
- Аудитория, возраст, опыт, число участников, формат, цель, место, материалы, цифровые инструменты, креативность и ожидаемый результат влияют на содержание. Недостающие условия явно обозначаются.
- Каждое упражнение содержит цель, материалы, организацию, дословную речь ведущего, пошаговые действия, правила, задания, вопросы, ожидаемый результат, переход и доступную альтернативу.
- Полный пакет включает паспорт, концепцию, подготовку, поминутный план, сценарий, интерактивы, практический продукт, рефлексию, заключение, оценку, готовые раздатки, адаптации и план слайдов.
- Времена этапов должны точно совпадать с общей продолжительностью. Короткие встречи имеют реалистичное число этапов.
- Добровольность, роль наблюдателя, доступность, запрет принуждения к личному раскрытию, клиническим диагнозам и опасным упражнениям. Чувствительные темы ограничены безопасным просвещением; ИИ не получает личные данные участников.

## Архитектура

Frontend: `/dashboard/ai/trainings`, отдельный `src/features/trainings/`, существующие auth, i18n, TanStack Query, история и очередь.

Backend: `src/trainings/`, kind `training.generate` в durable generation queue. Строгая схема входа и результата, серверные defaults и checks, существующие idempotency, reservations/refunds, ownership. Результаты хранятся в заданиях; новая таблица не требуется. Экспорт DOCX из сохранённого результата по owner-only endpoint.

## Дизайн

Сохраняем SanduAI: тёплый светлый фон, оранжевый акцент, зелёные смысловые маркеры, читаемый тёмный текст. Просторный рабочий интерфейс с одним главным действием, пронумерованными секциями и sticky summary. Параметры организации раскрываются по мере необходимости. Семантические controls, видимый focus, доступные ошибки, достаточный контраст, reduced-motion, адаптация от 375 px. Никаких фиктивных процентов и обещаний результата.

## Критерии приёмки

- Авторизованный пользователь находит модуль в своём сегменте и может создать материал с одной темой.
- Все восемь режимов возвращают соответствующий законченный продукт.
- Сервер отклоняет некорректный диапазон, несовпадающий тайминг и неполный контент до успешного расчёта.
- Результат доступен после обновления страницы и из истории; чужой job/export недоступен.
- Повтор транспорта не создаёт повторное списание, ошибка генерации проходит существующий refund flow.
- Word содержит реальный контент с казахскими символами, планом и раздатками; copy отражает весь материал.
- Проверены реальный API, внешний LLM, сохранение и отображение результата, desktop и mobile.

## Реализовано

- Отдельный рабочий интерфейс с 6 типами мероприятий, 15 группами аудитории и 8 режимами результата; RU/KK интерфейс, 5 языков материала, казахский по умолчанию.
- Примеры тем, необязательные условия и ресурсы, групповые параметры, автоматические возрастные длительности, локальный черновик по учётной записи.
- Durable queue, стоимость 30 токенов, восстановление по URL, пагинированная история, защита от повторной отправки и отмена задания.
- Просмотр всех разделов, упражнений и карточек, навигация по результату, полное копирование и Markdown, настоящий DOCX из сохранённого результата.
- Серверная проверка соответствия режима, точной суммы этапов, явных таймеров внутри упражнений, обязательных доступных альтернатив и материалов.
- Безопасные ограничения длительности внешнего запроса, ограниченное исправление ответа модели, возврат токенов при отказе, защищённый экспорт по владельцу.

## Локальный запуск

Текущий frontend: http://127.0.0.1:3000/dashboard/ai/trainings

Backend: http://127.0.0.1:8000, readiness: http://127.0.0.1:8000/health/ready

Проверки используют только локальные PostgreSQL (`127.0.0.1:55432`) и Redis (`127.0.0.1:56379`), отдельную QA-учётную запись. Её реквизиты не входят в git.

Для повторного запуска в двух PowerShell terminals из соответствующих репозиториев:

```powershell
# Backend (при запущенных локальных PostgreSQL и Redis)
.\scripts\dev-local.ps1

# Frontend
$env:NEXT_PUBLIC_API_BASE = 'http://127.0.0.1:8000'
npm run dev
```

Текущий сеанс запущен скрытыми локальными helper scripts в `.codex-tmp/start-training-backend.ps1` и `.codex-tmp/start-training-frontend.ps1`; там же сохраняются runtime logs. Они содержат конфигурацию только этого компьютера и намеренно не коммитятся.

## Проверка

- Frontend: 616 тестов в 89 suites, TypeScript, ESLint и production build успешно.
- Backend: автоматические проверки всех 8 режимов, defaults/границ, точного и вложенного тайминга, групп, provider repair, ownership/expiry, экспорта, очереди и токенов.
- Браузер: русская/казахская форма, переход из навигации, сохранение черновика после reload, загрузка реального полного пакета и отсутствие console errors проверены.
- Нативная проверка узкого экрана прервалась из-за невозможности инструмента достоверно определить URL окна Chrome. Мобильные CSS breakpoints реализованы, но визуальная мобильная проверка остаётся открытой.
- Word: реальный казахский полный пакет отрендерен в страницы для проверки шрифта, таблиц и переносов.
- Все восемь режимов проверены живыми запросами. Итоговый полный пакет: 6 этапов / 45 минут, 3 раздатки, 7 слайдов. Найденные исправления и ограничения проверки описаны в `TRAINING-PRO-VERIFICATION.md`.
